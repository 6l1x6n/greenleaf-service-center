# ТЗ (техническое задание) — сайт Greenleaf

## Архитектура

- **Сайт**: статик-ассеты в `public/` + Cloudflare Worker (`worker.js`, имя `mygreenleaf`).
- **Деплой**: только через git push — `.github/workflows/deploy.yml` (секрет `CF_API_TOKEN`).
  Ручной `wrangler deploy` из устаревшей копии перезатирается авто-деплоем по пушам.
- **Парсер каталога**: `scripts/parser/parser.py`, GitHub Actions (`parse-catalog.yml`).
  Запуски каждые 2 часа днём (Астана): 10:00–00:00 = cron `0 5,7,9,11,13,15,17,19 * * *`
  UTC + случайная задержка 0–3 мин. Все запуски «умные»: существующие товары — только
  количества по артикулам, новые артикулы создаются с полными данными один раз
  (в любом запуске). Полный прогон — `--full` (ручной). Учётка портала s240534,
  партнёр kz44326234. Подробности — `PARSING_GUIDE.md`.
- **Фото товаров**: хранятся локально в репозитории (`assets/images/products/`).
  Парсер выбирает вариант портала с наибольшим разрешением (оригинал до 800×800,
  `-shop` 600×600), сжимает Pillow (400 КБ / 800px, JPEG q82 / PNG для прозрачных).
  Низкокачественные (<400px) и битые файлы перекачиваются автоматически
  (`upgrade_low_res_photos`, лимит 400/прогон, идемпотентно).
- **Заказы**: KV `orders` (new/ready/confirmed/cancelled) + `orders_history` (архив суперадмина).
  Доступно онлайн = факт(парсер) + дельта − 2-мин холды − Σ new/ready − Σ confirmed
  после последнего синка. Подтверждение: резерв → продажа (остаток не меняется);
  после синка парсера заказ архивируется и не влияет на остаток. Отмена возвращает
  товар; удаление confirmed не возвращает.
- **Остатки и поправки**: публичный факт — `public/data/store-stock.json` (парсер).
  Воркер на лету применяет **постоянные поправки** KV `stock_deltas`
  (на сайте = факт + дельта; задаётся в кабинете СЦ/суперадмина — число с бейджем
  «Δ −20»/«Δ +5» под полем) и списания (продажи/брони). Для товаров без факта парсера —
  абсолютные значения KV `stock_edits`.
- **Данные**: публичный каталог `public/data/products.base.json` (виртуальный
  `/data/products.json` с оверрайдами суперадмина), остатки `store-stock.json`,
  накладные `moves.json`, карточки СЦ и заказы в Cloudflare KV (`SC_STORES`).
- **Кабинет**: вход только для СЦ и суперадмина. Таблицы товаров/остатков — пагинация
  по 100 строк с буфером несохранённых правок. Сброс правок — модалка с выбором
  параметров (цены, описания, статусы, приоритеты, скидки, скрытие, настройки филиалов).
  СЦ меняет свой пароль (логин — нет), может задать новый пароль портала, но не видит
  текущий. Пароль портала видит только суперадмин; сброс пароля — только суперадмин.
  Email владельца и флоу «Забыли пароль» удалены.
- **Каталог (публичный)**: товары подгружаются порциями (кнопка «Показать ещё»);
  в модалке товара фото целиком (object-fit: contain).
- **Безопасность**: пароли (портала, кабинетов, admin_creds, заявок) в KV зашифрованы
  AES-GCM (Worker-секрет `DATA_ENC_KEY`, формат `enc:v1:<iv>:<ct>`). Расшифровка — только
  для входа, панели суперадмина и `/api/parser-config` (по API-ключу). СЦ пароли не видны.
- **Секреты** (вне репозитория):
  - Cloudflare Worker secrets: `TG_BOT_TOKEN`, `TG_CHAT_ID`, `TG_ORDERS_CHAT_ID`, `STORE_CREDS`, `AUTH_HMAC_KEY`, `PARSER_API_KEY`
  - GitHub Actions secrets: `SC_LOGIN`, `SC_PASSWORD`, `CF_API_TOKEN`
  - Локальный `scripts/parser/config.json` — фолбэк для ручного запуска (gitignored)
